# VerifAI — Complete Backend Feature Inventory

This document provides a comprehensive inventory of all architectural components, modules, endpoints, and security boundaries across the VerifAI backend.

---

## 1. Inventory Matrix

| Component | File / Location | Responsibility | Input | Output | Dependencies | Database Interaction | Security Boundary |
|-----------|----------------|----------------|-------|--------|--------------|----------------------|-------------------|
| **Configuration** | `backend/app/core/config.py` | Centralized type-safe settings loaded from env vars and `.env` | Environment variables, `.env` file | `Settings` singleton via `get_settings()` | `pydantic-settings`, `pydantic` | Defines DB pool, timeouts, credentials | Uses `SecretStr` for `DATABASE_URL`, `JWT_SECRET`, `TAVILY_API_KEY`, Supabase keys |
| **FastAPI Application** | `backend/app/main.py` | App factory, lifespan hooks, middleware registration, router mounting | ASGI events, requests | ASGI responses | FastAPI, Starlette | Initializes/disposes async engine pool | Configures CORS, security headers, request ID propagation |
| **Request Correlation** | `backend/app/core/middleware.py` | ASGI middleware for request ID validation, generation, and timing | HTTP request headers (`X-Request-ID`) | Header injection on response, contextvar | Starlette, Python `uuid` | None | Sanitizes `X-Request-ID` against regex `^[A-Za-z0-9_-]{1,64}$` to prevent header/log injection |
| **Structured Logging** | `backend/app/core/logging.py` | JSON-structured and formatted logging with correlation ID | Log records | Formatted stdout log lines | Python `logging`, `contextvars` | None | Redacts credentials, tokens, sensitive document payloads |
| **Error Handling** | `backend/app/core/errors.py` | Standardized JSON error response formatting and app exceptions | Unhandled/handled exceptions | JSONResponse with status, code, message, request ID | FastAPI, Starlette | None | Masks internal stack traces, DB queries, and file paths |
| **Database Engine** | `backend/app/core/database.py` | SQLAlchemy 2.x async engine and sessionmaker lifecycle | `DATABASE_URL` from settings | `AsyncSession` generator | `sqlalchemy[asyncio]`, `asyncpg` | Connects to PostgreSQL, manages pool | Prevents connection leaks, timeouts at 3s connect / 30s pool |
| **Domain Models (Base)** | `backend/app/models/base.py` | Base declarative class, GUID type, timestamp mixin | ORM definitions | Mapped classes | SQLAlchemy 2.x | Base class for all tables | GUID type normalizes UUIDs across PostgreSQL and SQLite |
| **Domain Models (Verification)** | `backend/app/models/verification.py` | Tables: `verifications`, `claims`, `evidence_items`, `judge_evaluations`, `audit_records` | Domain records | SQLAlchemy mapped rows | SQLAlchemy 2.x | Primary relational store for verification truth | Cascading foreign keys, owner-scoped indexes |
| **Domain Models (Knowledge)** | `backend/app/models/knowledge.py` | Tables: `knowledge_documents`, `knowledge_chunks` | Ingested documents and chunks | SQLAlchemy mapped rows | SQLAlchemy 2.x | Namespace-isolated document and chunk store | Unique constraint `(owner_id, content_hash)`, owner-scoped queries |
| **Domain Models (User/Auth)** | `backend/app/models/user.py` | Table: `users` | Registration & profile data | SQLAlchemy mapped rows | SQLAlchemy 2.x | User credentials and RBAC records | Argon2id password hash storage, email/username uniqueness |
| **Domain Models (Ingestion)** | `backend/app/models/ingestion.py` | Table: `ingested_payloads` | Raw input payloads | SQLAlchemy mapped rows | SQLAlchemy 2.x | Audit store for captured payloads | SHA-256 payload hash tracking |
| **Security & Crypto** | `backend/app/core/security.py` | Password hashing (Argon2id), JWT encode/decode, RBAC enforcement | Passwords, tokens, credentials | Hashes, verified JWT claims, User identity | `argon2-cffi`, `pyjwt` | Reads user table on token verification | Fixed algorithm HS256, validates exp, iss, aud, sub |
| **Authentication API** | `backend/app/api/v1/endpoints/auth.py` | Endpoints: `/auth/register`, `/auth/login`, `/auth/me` | Register/login schemas, Bearer token | JWT tokens, User profile response | FastAPI, Security module, DB | Queries and inserts into `users` table | Password validation, rate limiting, never returns hash |
| **Rate Limiter** | `backend/app/core/rate_limit.py` | In-memory token-bucket / sliding-window rate limiting | Client IP or user ID, endpoint key | Allow or raise HTTP 429 | Python `time`, `collections` | None | Protects login, registration, verification, KB upload/search |
| **Resource Abuse Controls** | `backend/app/core/resource_limits.py` | Maximum payload sizes, claim counts, concurrent jobs | Incoming request metadata | Pass/raise AppError | Pydantic, FastAPI | Bounded query concurrency | Maximum 3 concurrent verification jobs per user |
| **Verification API** | `backend/app/api/v1/endpoints/verification.py` | Endpoints: `POST /verification`, `GET /verification/{id}`, `GET /verifications` | Verification request payload, query params | `VerificationResponse`, list envelope | Orchestrator, Auth, DB | Reads/writes `verifications` and relations | Owner isolation: users can only read their own verifications |
| **Verification Orchestrator** | `backend/app/modules/verification/orchestrator.py` | 7-stage verification workflow: extract, classify, route, retrieve, judge, arbitrate, audit | `VerificationCreateRequest`, `owner_id` | `VerificationResponse` | Claims, Evidence, Judging, Knowledge | Persists completed job and audit logs | Ensures evidence insufficiency yields UNKNOWN |
| **Claim Extractor** | `backend/app/modules/claims/extractor.py` | Decomposes raw response into discrete propositional claims | Text string, `max_claims` | `list[ExtractedClaimItem]` | Python `re` | None | Enforces `text[start:end] == claim_text`, prevents span overlap |
| **Claim Classifier** | `backend/app/modules/claims/classifier.py` | Classifies claims into 6 PRD taxonomies (`FACTUAL`, `OPINION`, etc.) | Atomic claim text | `ClassificationResult` | Python `re` | None | Non-factual claims bypass external verification safely |
| **SSRF Safety Validator** | `backend/app/modules/evidence/security.py` | Inspects target URLs to block private/internal/cloud addresses | URL string | `bool` (safe/unsafe) | Python `ipaddress`, `urllib.parse` | None | Blocks 0.0.0.0/8, 10/8, 127/8, 169.254/16, 172.16/12, 192.168/16, IPv6, AWS/GCP metadata |
| **External Evidence (Tavily)** | `backend/app/modules/evidence/tavily_retriever.py` | Primary web search retriever using Tavily Search API | Claim query text | `list[RetrievedEvidenceItem]` | `httpx`, `tavily-python` | None | Validates result URLs through SSRF filter, bounded snippets |
| **External Evidence (DDG)** | `backend/app/modules/evidence/duckduckgo_retriever.py` | Secondary fallback search retriever using DuckDuckGo | Claim query text | `list[RetrievedEvidenceItem]` | `duckduckgo_search` | None | SSRF filtering, timeouts, bounded result count |
| **External Evidence (Nightcrawler)** | `backend/app/modules/evidence/nightcrawler_retriever.py` | Tertiary safe fallback using Wikipedia REST API | Claim query text | `list[RetrievedEvidenceItem]` | `httpx` | None | Connects only to `en.wikipedia.org`, strips HTML markup |
| **Local Evidence (Hermetic)** | `backend/app/modules/evidence/local_retriever.py` | Hermetic in-memory passage retriever for dev/test | Claim text | `list[RetrievedEvidenceItem]` | None | None | Hermetic baseline for deterministic testing |
| **Knowledge Base Ingestion** | `backend/app/modules/knowledge/ingestion.py` | Ingestion, filename sanitization, validation, hashing, chunking | File bytes/text, MIME type, filename | `IngestionResult` with chunks & offsets | `hashlib`, Python `re`, `json` | Checks duplicate content hash | Sanitizes path traversal, bounds size to 5MB, SHA-256 hash |
| **Knowledge Base Service** | `backend/app/modules/knowledge/service.py` | Document storage, chunk storage, search, deletion | Document payloads, query, `owner_id` | `KnowledgeDocument`, `KnowledgeChunk` | SQLAlchemy 2.x | CRUD on `knowledge_documents` and `chunks` | All operations strictly scoped by `owner_id` |
| **Knowledge Base Retriever** | `backend/app/modules/knowledge/retriever.py` | Lexical search over owner's chunks, sufficiency scoring | Claim text, `owner_id` | `KBSearchResult` with sufficiency status | Python `re`, stop-words | Queries chunks by `owner_id` | Scores chunks via token overlap, classifies sufficiency |
| **KB-First Evidence Orchestration** | `backend/app/modules/verification/orchestrator.py` | Queries private KB first; skips external if KB is sufficient | Claim, `owner_id`, options | Evidence set | PrivateKBRetriever, LiveWebRetriever | Audits search events | External search skipped unless corroboration forced |
| **Independent Judges** | `backend/app/modules/judging/` | Rule-based, Semantic, and Model judges evaluate claims vs evidence | Claim text, evidence items | `JudgeEvaluationData` | Deterministic rules, regex | None | Prompt-isolation boundary: untrusted evidence cannot hijack logic |
| **Judge Disagreement Engine** | `backend/app/modules/judging/disagreement.py` | Measures consensus and inter-judge disagreement | Evaluations from judges | Disagreement metrics | Python `dataclasses` | None | Flags divergent verdicts, detects ambiguity |
| **Decision Engine** | `backend/app/modules/judging/decision.py` | Produces final claim verdict: `SUPPORTED`, `CONTRADICTED`, `UNKNOWN` | Claim, evidence, evaluations | Verdict and confidence | Python `math` | None | Strict sufficiency: insufficient evidence yields UNKNOWN |
| **Audit Trail** | `backend/app/models/verification.py` | Records immutable lifecycle events for verifications | Event name, stage, status, message | `AuditRecord` rows | SQLAlchemy 2.x | Writes to `audit_records` table | Append-only audit record linked to verification job |
| **Interactive CLI** | `scripts/verifai_cli.py` | Diagnostic, demonstration, and developer terminal interface | Terminal input, flags | Rich console tables, trees, panels | Click, Rich | Optional direct DB or HTTP API | Diagnostic tool; never bypasses backend verification truth |
| **Benchmark Suite** | `benchmark/` | 100-case dataset, validation, metrics, quality gates, freezing | Benchmark JSON cases | Metrics reports, pass/fail gates | Pydantic, pytest | None | Independent ground-truth validation suite |
| **Automated Tests** | `backend/tests/`, `benchmark/tests/` | Unit, integration, security, SSRF, taxonomy, matrix suites | Test inputs | Assertions | Pytest | SQLite/PostgreSQL test engines | Hermetic verification of security and verification invariants |
| **CI/CD Pipeline** | `.github/workflows/` | GitHub Actions for linting, type-checking, testing, benchmarking | Git push/PR triggers | Workflow pass/fail status | GitHub Actions runner | Service containers for PostgreSQL | Blocks merge if quality gates fail |
